Quickstart

Use a private local session file created from your own browser session. The package never needs a live session file inside the repository.

from xapiweb import XClient
from xapiweb.resources.timelines import extract_tweets

x = XClient.from_session_file("my_data.json")
print(x.health().status)
print(x.me())

for tweet in extract_tweets(x.timelines.home(count=10)):
    print(tweet["author"], tweet["text"][:80])

Authentication

Sign in to X in a desktop browser. In developer tools, copy the complete Cookie request header and the x-csrf-token request header. The CSRF value must match the ct0 cookie value.

Never publish credentials. Keep my_data.json, cookies, bearer tokens, CSRF tokens, screenshots, logs, and generated caches out of GitHub, PyPI, and issue trackers.
from xapiweb import XClient
x = XClient(cookie="<full-cookie>", csrf_token="<ct0-value>")
print(x.health().status)  # 200 means connected

Read the full Sinhala connection guide for browser setup and troubleshooting.

Responses and errors

Each request returns a Response with status, data, raw, ok, get(), and summary().

TypeUse
XAuthErrorSession expired or authentication rejected.
XRateLimitErrorRate limit or temporary server refusal.
XTxnErrorTransaction or endpoint response could not be verified.
XValidationErrorInput does not satisfy the operation contract.
XVerifyErrorState-changing operation was not confirmed by a reread.

Security and responsible use

Use xapiweb only with accounts, sessions, and data you are authorized to control. Keep request pacing conservative and respect X terms, privacy requirements, rate limits, and applicable law.

Private sessionsStore session files locally with restrictive permissions. Do not commit them.
Side effectsWrites, follows, moderation, DMs, and deletes can affect real accounts. Use explicit confirmation where supported.
Unofficial clientWeb contracts can change. Pin versions and review errors before retrying.
Safe distributionThe published package contains source code but no user session credentials.

Troubleshooting

HTTP 401 or XAuthError

Recapture the browser Cookie and ct0 values. Confirm the browser session is still logged in.

403, 429, or XAutomationFlag

Stop bursts, wait, and increase min_interval. Do not run repeated retries against a flagged session.

XVerifyError after a write

Check that the operation used the correct original ID and that the state reread completed.

Transaction or 404 errors

Wait and retry conservatively. Endpoint contracts can change when X updates its web client.

Tests

The offline suite does not contact X and validates imports, parsing, response handling, guards, media helpers, and notifications.
